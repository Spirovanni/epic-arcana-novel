# Overview  
ChronoScriptor is an AI-assisted interactive storycrafting environment built for speculative fiction authors working with time travel, tarot-based magic systems, and complex narrative arcs. It enables writers to build and manage chapters connected to timelines, characters, Trionfi mechanics, and evolving lore. Optimized for Sudowrite-style drafting and Epicarcana-based tracking, it integrates Neon as the core database for dynamic content linking across your novel.

# Core Features  
- **Chapter-Centric World Map**  
  - Connect chapter events to precise locations and lore.
  - Clickable map reveals linked chapters, Trionfi card effects, and setting changes.
  - Designed to support chapter clustering per region or timeline.

- **Timeline & Paradox System**  
  - Track chapter branches across Alpha, Beta, and Gamma timelines.
  - Highlights paradox triggers, convergence points, and key divergences.
  - Allows chapter-level anchoring to specific timeline threads.

- **Trionfi Card Engine**  
  - Embed Trionfi cards into chapters, scenes, and character moments.
  - Tracks card usage, combinations, costs, forbidden overlaps.
  - Syncs with Neon to reflect card state changes across chapters.

- **Chapter Builder with Sudowrite Sync**  
  - Markdown-based editor with metadata: POV, emotion, card used, timeline effect.
  - Exports to Sudowrite for drafting, imports style and tone feedback into JSON structure.
  - Integrated with Epicarcana for visual tracking of chapter completion and quality.

- **Character Arc & Relationship Visualizer**  
  - Graph-style matrix connecting characters, chapter arcs, and Trionfi affinities.
  - Timeline filters: see character status across all timelines.
  - Supports love triangles, betrayal arcs, and redemptive loops.

- **Lore & Narrative Codex**  
  - Unified encyclopedia for timeline events, places, factions, artifacts, and prophecies.
  - Auto-tags references found in chapters and links back to Neon entries.
  - Filterable by Trionfi, timeline, or location type.

# Technical Architecture  
- **System Components**:  
  - Next.js 15+ (App Router)
  - TailwindCSS (UI styling)
  - Neon (PostgreSQL with branching support)
  - Cursor IDE + Taskmaster AI (OpenAI/Claude endpoints)
  - Optional: Drizzle ORM or Prisma client for Neon

- **Data Models**:  
  - `chapters`: id, title, number, summary, POV, trionfi_card_ids[], location_id, timeline_id, draft_status, style_notes
  - `timelines`: id, name, branch_name, convergence_events[], paradox_flags[]
  - `characters`: id, name, bio, arc_stages[], trionfi_affinities[], relationship_links[]
  - `scenes`: id, chapter_id, name, beat_type, conflict, resolution, card_used, word_count
  - `trionfi_cards`: id, name, arcana_type, divine_effect, activation_method, forbidden_combos[]
  - `locations`: id, name, type, sensory_details, arcana_linked, factions_present
  - `lore_entries`: id, keyword, category (location, character, item, event), content, tag_links[]

- **APIs and Integrations**:  
  - **Sudowrite Sync**:
    - `/api/sync/chapter-style`
    - `/api/prompt/sudowrite-draft-upload`
  - **Taskmaster AI**:
    - `/api/prompt/scene-analysis`
    - `/api/prompt/card-forecast`
    - `/api/prompt/arc-consistency`
  - Map: Mapbox (preferred) or Leaflet.js
  - Timeline Visualization: ReactFlow with Neon timeline joins

- **Infrastructure Requirements**:  
  - Vercel or Netlify for frontend deployment
  - Neon for relational + branching database
  - GitHub CI for pull-based deployment flows
  - n8n webhook integrations for chapter event triggers and JSON file exports

# Development Roadmap  
## MVP Goals  
- Scene & Chapter Builder (Sudowrite-ready)
- Interactive Timeline Tracker (basic branch view)
- Character Visual Matrix (arc + Trionfi overlay)
- Trionfi Index + Chapter Linking
- Lore Codex (searchable + auto-tagged)
- Neon Schema + CRUD UI for chapters

## Future Enhancements  
- Paradox Validation System (with AI feedback on risk)
- Chapter Impact Graph (visualize ripple effects)
- Multiplayer Timeline Editing
- Sudowrite AI Feedback Summarizer (style feedback extraction)
- Auto-linked poetic symbolism analyzer
- Export system to generate submission-ready manuscript from Neon data

# Logical Dependency Chain  
- **Core Foundation**:
  - Neon DB schema + Vercel front-end layout
  - Auth shell + route protections (Next.js middleware)

- **Writing Hub First**:
  - Build Chapter Builder → integrate with Sudowrite sync
  - Add Trionfi indexing + card-to-chapter mapping
  - Hook Lore Codex to Neon for auto-tagging

- **Advanced Logic Later**:
  - Add timeline branching once core content is stable
  - Introduce Taskmaster endpoints to refine tone, paradoxes, arc cohesion

# Risks and Mitigations  
- **Sudowrite format drift**: create JSON->Markdown sync bridge, validate structure in both directions
- **Timeline linking bugs**: use strong Neon foreign keys, staged data updates
- **Too much AI feedback**: prioritize structure suggestions first, style tuning later
- **Early burnout**: MVP should support complete novel start-to-finish for 1 book
